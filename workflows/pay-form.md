## 給与フォームの内訳（2026-08-26 に作り直した）

固定6欄（基本給／機長手当／交通／その他／プロフィットシェア／年金）は**日本の大手の明細**しか
入らない形だった。Flight Pay・Sector Allowance・Productivity Pay・Reserve のように、
**変動給の建て付けは会社ごとに違う**。オーナー指示で作り直した。

**目的は明細の再現ではない。** 固定／変動／変動の理由／その他の現金の4つに分けて、
航空会社をまたいで比べられる形にすること。

### ⚠️ 総支給と内訳は**排他ではない**
- 本人が入れた「その月の総支給額」を**内訳の合計で上書きしない**（オーナー指示）。
  内訳を開いても欄は生きたまま・読み取り専用にしない・閉じても消さない。
- **一致を送信の条件にしない。** 差はレポートの図が「どの項目にも入れていない分」として灰色に描く
  （[pay-viz.js](pay-viz.js) の `segments()`）。
- 画面が口を出すのは**内訳の合計が総支給を超えたときだけ**（`#pd-over` の1行）。
  それでも送信は止めない。**足りないときは何も言わない**（説明できない残りは普通のこと）。
- 年換算は昔から総支給が正（[db/pay-reports.sql](db/pay-reports.sql) の `pv_annual_total` の
  `coalesce` の第1引数）。だから**この変更で年収の数字は1円も動かない**。
- ⚠️ 排他を復活させると DEEP PAY の「内訳あり」判定と `pay-viz` の `partial` が同時に壊れる。
  `db/test-pay-reports.mjs` と `db/test-form-contract.mjs` が字と実際の値の両方で見張っている。

### 入れ子の約束（逆にすると図が壊れる）
| 画面のブロック | 寄せる列 |
|---|---|
| 基本給（＋「該当なし」）【常時表示】 | `base_pay` |
| ＋ Flight time 保証手当 / 職務手当 | ★`guarantee_pay`（2026-08-26 に足した列）|
| ＋ RANK / POSITION の固定手当 | `command_pay` |
| ＋ **変動給**（行で何本でも） | 合計 → `flight_variable_pay` |
| ＋ **その他の現金手当**（行で何本でも） | 合計 → `other_allowance` |

★**最初は基本給だけを出す。**残り4つは「＋」で足す（オーナー指示の Progressive Disclosure）。
★**保証給は基本給に足し込まない。**日本＝基本給、米国＝保証給が下限で、意味が違う。
1つの列に混ぜると二度と割れず、レポートの緑の切れが「基本給」と嘘をつく。
保証**時間**は §2 の `f-guar`（`guaranteed_hours`）で既に聞いている。**二度聞かない。**

★**この欄の札は「Flight time 保証手当 / 職務手当」の併記**（2026-08-26 その3 オーナー指示）。
同じ金額が、会社によって Minimum Guarantee とも保証給とも**職務手当**とも書かれる。
片方の呼び名しか出していないと、もう片方の人は自分の明細のどこを写せばいいのか分からない。
**列は `guarantee_pay` のまま・DB は1バイトも変わらない。**英語は "Flight time guarantee / Duty allowance"。
⚠️ **「職位手当」（`command_pay`）とは別物。**あちらは4番目のまま動かさない
（位置も名前も触らない。hint が「職務手当（上の欄）とは別」と1行で断っている）。
レポートの凡例（[my-value.js](my-value.js) / [pay-tracker.js](pay-tracker.js) の `segGuarantee`）も
同じ併記に揃えてある。**キー名 `guarantee` は変えない。**

⚠️ **`other_allowance` は 変動給＋その他 の合計、`flight_variable_pay` はその内訳。**
[pay-viz.js](pay-viz.js) が `flight_variable ⊂ other` として引き算しているので、逆にすると
支給構成の円が二重計上になる。
- **交通（月）とその他手当の専用欄は画面から消えた**（`<input type="hidden">`＝明細読み取り専用）。
  人が打つのは繰り返し行のほう。列は残す（過去データが使う）。
- Housing / Per Diem は内訳の**前**で全員に聞いている。ここで二度聞かない。
- 教官・審査・組合などの**追加ロールの手当はここに入れない**（役割ごとのモジュールで別に聞く）。
  ★教官・訓練（その3）・審査・査察（その4）・組合・乗員代表（その5）・
  管理・マネジメント（その6）・その他の兼務・配属（その7）。**6つすべてに節がある。**
- ★**計算をユーザーにさせない**（2026-08-26 オーナー指示）。明細に書いてある**金額だけ**を聞く。
  足し算・単価計算・時給換算・比率計算はこちらでやる。だから変動給の行に
  **支給単価・ルールの欄を作らない**（`¥4,500 / Block Hour` を打たせない）し、
  保証給も**「保証時間 × 単価」を計算させない**（金額が明細で分かるときだけ入れてもらう）。
- ★★**こちらで割り算・掛け算して出せる数は、そもそも聞かない**（2026-08-26 その4 オーナー指示
  「今後ともサイトで計算したらわかるようなことはわざわざパイロットに聞かないで」）。
  上の1行の一般形で、**新しい欄を足すたびに通す問い**。
  「1回あたりの支給額」「1日あたりの支給額」「時間単価」は
  **今月の額 ÷ 数量**でこちらが出せるので**欄を作らない**（2026-08-26 その4 に教官の節から削除した）。
  逆に**数量（回数・日数・Sessions 数）は残す** ── 明細を見ないと分からない数で、
  これが無いと会社をまたいで「1回あたりいくら」を比べる材料が消える。
- ★**変動給の行の並びは 種類 → 支給額 → 明細上の名称**（2026-08-26 その2 オーナー指示）。
  金額を先に書かせると、区分は「あとで」になって選ばれない。
- ★**「書かなくても大丈夫です」と書かない。**そう書いた欄は書かれなくなる（オーナー指摘）。
  選択肢の先頭は「選んでください」。任意の欄（明細上の名称）も、任意だとは画面に書かない。
  `db/test-form-contract.mjs` の ⑦-b が、変動給の節に
  「任意 / 書かなくて / optional / leave blank」が無いことを字として見張っている。

### 行そのものは `pay_items jsonb` に残す
```json
{"v":1,"fixed_none":false,
 "variable":[{"amount":180000,"basis":"block","label":"Flight Pay"}],
 "other":[{"amount":12000,"label":"通勤手当"}]}
```
合計だけを既存列へ寄せるので、過去の集計・レポートの図・k≧5 のベンチマークが1つも壊れない。
検品は `pv_validate_pay_payload`（8000文字・配列40件まで・壊れた JSON は投稿ごと落とさず捨てる）。
`basis`（変動給の種類）は**10択**で日英とも同じ並び ──
`block` / `duty` / `sector` / `overtime` / `reserve` / `night` / `weekend` / `holiday` /
`other` / `unknown`。★**変動給の行を足した人にだけ必須**（2026-08-26 その2）。
逃げ道は末尾の `unknown`（「わからない」）で、行を1本も足していない人は素通りする。
判定は `pdRead('var')` に任せる（＋を押しただけの空の行を落とす条件を2か所に書かない）。⚠️ **`rule` を書き戻さない**（2026-08-26 に消した欄）。

### 教官・訓練の手当（2026-08-26 その3）

役割ごとのモジュールの1本目。**§3「給与の内訳」の `</details>` の直後**に独立したブロック
（`#s3-instr`）を置いた。**§1で「教官・訓練担当」を選んだ人にしか出ない。**
外すと畳んで**中身も消える**（画面に無いものを黙って送らない）。

**狙いは明細の再現ではない。**(1) 何の訓練を担当しているか (2) 追加の支給があるか
(3) 何を単位に払われるか (4) 今月いくら出たか の4つを、会社をまたいで同じ形で持つこと。
**教官の仕事を時間に換算させない**（オーナー指示）。

| | 保存先 |
|---|---|
| 今月の教官・訓練の支給額 | ★列 `instructor_pay`（2026-08-26 その3 に足した列）|
| 担当訓練・名称・支給の有無・支給単位・数量 | `pay_items.instructor`（オブジェクト1つ）|

```json
{"v":1,"variable":[],"other":[],
 "instructor":{"trainings":["line","sim"],"label":"Training Captain (TRI)",
               "extra":"separate","method":"session",
               "amount":4200,"qty":3}}
```

- ⚠️ **職位手当（`command_pay`）・変動給（`flight_variable_pay`）・その他（`other_allowance`）へ
  二重入力させない。**別の入れ物に持つのがその実装そのもので、**どれにも足し込まない**。
  欄の hint も「この額は職位手当・変動給・その他の現金手当には入れないでください」と言っている。
- **総支給（`f-gross`）は書き換えない。**教官の額は総支給の**中に入っている前提**（オーナー確認）。
  `monthlyDetail()` に `num('f-instructor')` を足してあるので、
  合計が総支給を超えたときだけ `#pd-over` の1行が出る。**送信は止めない。**
  年換算は今までどおり総支給が正なので、**この列で年収の数字は1円も動かない**。
- ★**必須は1つも置いていない**（`req-tag` を書かない＝段のゲートも送信の条件も動かない）。
  「含まれている」「追加の支給はない」を選んだ人は**2〜3クリックで終わる**
  （金額・支給単位・数量は「別途支給されている」を選ぶまで出ない）。
- ★**単価の欄は無い**（2026-08-26 その4 に削除）。**今月の額 ÷ 数量**でこちらが出せる数を
  人に転記させない（上の★★）。**数量は残す。**
  ⚠️ 過去の行の `pay_items.instructor.rate` はそのまま残っている（読まなくなっただけ）。**消しに行かない。**
- ★**数量のラベルは `<option>` の `data-qty` が持つ。**
  JS に日本語を置かない＝日英で同じコードが動く。月額固定は数える物が無い＝`data-qty` が空で欄ごと出さない。
- ★**「支給単位」**（2026-08-26 その4 オーナー指定。前は「何に対して払われるか」）。
  英語は "Pay unit"。**教官と審査で同じ語**を使う。
- 支給単位（`method`）は**7択**で日英とも同じ並び ── `monthly` / `duty` / `session` /
  `sector` / `hour` / `course` / `other`。
- ⚠️ **`pay_items` の組み直し（[db/pay-reports.sql](db/pay-reports.sql)）に `'instructor'` を足し忘れると、
  教官の中身が黙って消える。**あそこは `jsonb_build_object` で知らないキーを落とす作り。
- ⚠️ [db/pay-rows.sql](db/pay-rows.sql) は `pv_annual_total` の**引数の並びを写している**
  （登録前の預かりを読む側）。列を足したらここも足す。忘れると同じ明細から
  **本棚と預かりで違う年収**が出る（`db/test-pay-rows.mjs` の ▼12 が突き合わせている）。
- 支給構成の円では**自分の色を持つ1切れ**（[pay-viz.js](pay-viz.js) の `SEG` の `instructor`）。
  [my-value.js](my-value.js) の3本のバケツでは **`vari`（変動）**
  ── セッション・日数で月ごとに変わるのが普通のため。入れ忘れると
  `db/test-value-breakdown.mjs` が「スライスの取りこぼし」で落ちる。
- `pv_pay_comp` では **`o`（その他の手当）**に入る（職位手当・交通費と同じ扱い）。
  `guarantee_pay` が **`m`（月々の支給）**なのと**違う**ので、混ぜない
  ── 混ぜると DEEP PAY の「基本給の割合」が教官の手当で汚れる。
- 管理者メールは**触っていない**（`instructor_pay` を読まない＝金額は1文字も出ない。
  `pay_items` の行数は `variable` / `other` の配列だけを数えていて、
  `instructor` は**オブジェクト**なので数にも入らない）。**Edge Function の Deploy は不要。**
- 明細読み取り（[payslip.js](payslip.js)）は教官の欄に**何も入れない**（`KIND_FIELD` を増やしていない）。

### 審査・査察の手当（2026-08-26 その4）

役割ごとのモジュールの2本目。**`#s3-instr` の直後**に独立したブロック（`#s3-exam`）を置いた。
**§1で「審査・査察（Examiner / Check）」を選んだ人にしか出ない。**
外すと畳んで**中身も消える**（教官と同じ）。

**狙いは審査業務の実態調査ではない。Examiner という役割を持つと、どんな追加報酬があるのか**を
会社ごとに比べられる形にすること。

| | 保存先 |
|---|---|
| 今月の審査・査察の支給額 | ★列 `examiner_pay`（2026-08-26 その4 に足した列）|
| 担当 Check・名称・支給の有無・支給単位・数量 | `pay_items.examiner`（オブジェクト1つ）|

```json
{"v":1,"variable":[],"other":[],
 "instructor":{…},
 "examiner":{"checks":["sim","line"],"label":"TRE","extra":"separate",
             "method":"check","method_label":null,"amount":3600,"qty":2}}
```

- ★★**二重計上を止めるのがこの節の中心**（オーナー指示）。教官も審査も担当している人は、
  同じ手当を2回書きうる。仕掛けは2つ ──
  ① 「審査業務に対する追加の支給」の**5択に `with_instructor`（Instructor / Training 手当と
  まとめて支給される）を必ず置く**。これを選んだら**金額の欄を出さない**
  （その額は `instructor_pay` 側に入っている）。**選択肢から外さない。二重入力を止める唯一の道。**
  ② 額は**専用の列 `examiner_pay`**。職位手当（`command_pay`）・変動給（`flight_variable_pay`）・
  その他（`other_allowance`）・**教官（`instructor_pay`）のどれにも足し込まない**。
- 5択は `separate` / **`with_instructor`** / `included` / `none` / `unknown`、
  支給単位（`method`）は**6択** `monthly` / `check` / `session` / `duty` / `hour` / `other`
  （日英とも同じ並び）。教官の7択とは**違う**ので写さない（審査に `sector` / `course` は無い）。
- **総支給（`f-gross`）は書き換えない。**`monthlyDetail()` に `num('f-examiner')` を足してあるのは
  合計が総支給を超えたときの `#pd-over` の1行のためだけ。**送信は止めない。**
  年換算は総支給が正なので、**この列で年収の数字は1円も動かない**。
- ★**必須は1つも置いていない**（`req-tag` を書かない）。「追加報酬はない」「給与に含まれている」
  「Instructor とまとめて」を選んだ人は**数クリックで終わる**。
  **数量が分からなくても、今月の額だけで保存できる。**
- ★**単価の欄は作らない**（①のルール）。数量のラベルは `<option>` の `data-qty`。
- ⚠️ **`pay_items` の組み直し（[db/pay-reports.sql](db/pay-reports.sql)）に `'examiner'` を
  足し忘れると、審査の中身が黙って消える。**`jsonb_build_object` で知らないキーを落とす作り。
- ⚠️ [db/pay-rows.sql](db/pay-rows.sql) は `pv_annual_total` の**引数の並びを写している**。
  列を足したらここも足す（`db/test-pay-rows.mjs` の ▼12 が本棚と預かりを突き合わせている）。
  ★署名を書いている場所は4つ（`drop` / `revoke` / `comment` / `to_regprocedure`）。
  1つでも古い引数のままだと**ファイルごと流れない**。
- 支給構成の円では**自分の色を持つ1切れ**（[pay-viz.js](pay-viz.js) の `SEG` の `examiner`＝
  `#0f766e`＝ブランドの `--pv-teal`）。[my-value.js](my-value.js) の3本のバケツでは
  **`vari`（変動）**（教官と同じ理由）。入れ忘れると `db/test-value-breakdown.mjs` が
  「スライスの取りこぼし」で落ちる。
- `pv_pay_comp` では **`o`（その他の手当）**（教官と同じ）。`m` に混ぜない。
- 管理者メールは**触っていない**（`examiner_pay` を読まない＝金額は1文字も出ない。
  `pay_items` の行数は `variable` / `other` の配列だけを数えていて、`examiner` は
  **オブジェクト**なので数にも入らない）。**Edge Function の Deploy は不要。**
- 明細読み取り（[payslip.js](payslip.js)）は審査の欄に**何も入れない**（`KIND_FIELD` を増やしていない）。

### 組合・乗員代表の手当（2026-08-26 その5）

役割ごとのモジュールの3本目。**`#s3-exam` の直後**に独立したブロック（`#s3-union`）を置いた。
**§1で「組合・乗員代表（Union / Pilot Representative）」を選んだ人にしか出ない。**
外すと畳んで**中身も消える**（教官・審査と同じ）。

**狙いは組合制度の調査ではない。組合・乗員代表の役割が、その月の給与データにどう出ているか**だけ。
だから聞くのは**4つ**（日数・追加の支給の有無・金額・支給元）。
Committee 種別・Union 内の役職名・Negotiation / Safety の活動内容・給与保障制度は**聞かない**
（オーナー明記。項目を増やさない）。

| | 保存先 |
|---|---|
| 今月の追加支給額 | ★列 `union_pay`（2026-08-26 その5 に足した列）|
| 活動日数・支給の有無・支給元 | `pay_items.union`（オブジェクト1つ）|

```json
{"v":1,"variable":[],"other":[],
 "instructor":{…},"examiner":{…},
 "union":{"days":12,"extra":"yes","source":"union","amount":3000}}
```

- ★★**ここだけ教官・審査と違う ── `monthlyDetail()` には条件つきで足す。**
  組合の手当は**支給元が Union / Association のことがあり、その額は会社の明細に載っていない**。
  そのまま足すと「内訳の合計が総支給を超えています」（`#pd-over`）が**嘘で出る**。
  判定は `unionInGross()` の1か所だけが持ち、**支給元が `airline` か `both` のときだけ**足す。
  ⚠️ 素直に足す形（教官・審査と同じ書き方）に直さない。
  ⚠️ 逆に SQL 側（`pv_annual_total` の内訳の枝）は**条件なしで足す**。あちらは総支給と
  突き合わせていないので、条件を写すと組合員のぶんが年換算から落ちる。
- **総支給（`f-gross`）は書き換えない。**年換算は今までどおり総支給が正なので、
  **この列で年収の数字は1円も動かない**。
- ★**二重計上させない。**額は**専用の列 `union_pay`**。職位手当（`command_pay`）・
  変動給（`flight_variable_pay`）・その他（`other_allowance`）・教官（`instructor_pay`）・
  審査（`examiner_pay`）の**どれにも足し込まない**（欄の hint も同じことを言っている）。

### 超過の注意は、その額を打った欄の下に出る（2026-08-27）

「内訳の合計が、上の総支給額を超えています」は**1文・1条件のまま**（`gross > 0 && monthlyDetail() > gross + 1`）。

### 明細から入るもの・入らないもの（2026-08-27）

明細を落とすと [parse-payslip](supabase/functions/parse-payslip/index.ts) が読んで、
[payslip.js](payslip.js) の `apply()` がフォームの欄に書き込む。
**読み取り側はフォームより後から追いかける形なので、欄を足したらここも足す**
（2026-08-26/27 の作り直しのあいだ、保証給・変動給の種類・教官・審査は
**フォームには在るのに読み取り側の語彙に無い**状態が数日続いた。画面は普通に動いたまま、
明細から入った人だけ内訳が薄くなる、という静かな壊れ方をする）。

| 入る | 行き先 |
|---|---|
| 基本給 | `f-base` |
| **Flight time 保証手当 / 職務手当** | `f-guarantee`（★2026-08-27）|
| 職位手当 | `f-command` |
| **変動給** | ★**行**（`tpl-pd-var`）＝手で打った人とまったく同じ入れ物。種類（`basis`）も入る |
| 住宅 / パーディアム / 交通 | `f-housing` `f-perdiem` `f-transport` |
| 今月のボーナス / プロフィットシェア | `f-bonus-mo` `f-profit` |
| **教官 / 審査** | ★`f-instructor` / `f-examiner`（＋役職のチェックと「別途支給されている」まで）|
| 総支給 / 手取り / 控除合計 | `f-gross` `f-netpay` |
| 対象月 / 通貨 | `f-year` `f-month` `f-currency` |
| フライトタイム / 勤務時間 / **保証フライトタイム** | `f-block` `f-duty-h` / ★`f-guar` |

| 入らない | 理由 |
|---|---|
| **組合・乗員代表** | プロンプトが「**組合費・組合の名前を返してはいけない**」と言っている。どの組合に居るかは最も機微な情報で、`label` から漏れる道を作らない |
| **管理・マネジメント / その他の兼務・配属** | 明細に決まった印字が無い。誤分類は**データを黙って汚す**（節は §1 のチェックでしか出ないので、本人に任せるほうが正しい）|
| **年金（`f-pension`）** | ★**`pension` という kind を作らない。** 日本の明細の「厚生年金」は**控除**であって支給ではない。kind を作ると、控除の行が収入として立つ道が開く |
| 支給単位・数量・担当訓練 | 明細から分からない。本人が足す（空のまま出しても送信は止まらない）|

- ★**`職務手当` を `guarantee` にしない。あれは `command`。**
  フォームの札が「Flight time 保証手当 / 職務手当」の併記なのは、**同じ額の呼び名が会社で違う**という話。
  日本の明細の職務手当は今までどおり `command`。ここを混ぜると日本のユーザー全員の内訳が壊れる。
- ★**二重計上の境目は1点だけ。** `flight_variable` の額は、**行に載ったら `f-var-sum`、
  載らなければ `f-flightvar`**。`flight_variable_pay = sumField('f-flightvar','f-var-sum')` /
  `other_allowance = sumField('f-other','f-var-sum','f-oth-sum')` なので、
  **どちらの経路でも両方に1回ずつだけ入る**＝年収も `pay-viz` の `flight_variable ⊂ other` も1円も動かない。
  `sumKind()` が `r.row` を持つ行を飛ばすのがその実装（`db/test-payslip-extras.mjs` の ②-b が値で見張っている）。
- 教官・審査の額は `f-other` にも `f-command` にも**足し込まない**（専用列があることがその実装そのもの）。
- **6択（`UNC_CHOICES`）は広げない。** `asked` の語彙は
  [db/pay-reports.sql](db/pay-reports.sql) の `pv_label_hints` が門になっていて、
  広げるとオーナーに SQL をもう1枚貼らせることになる。
- 明細を**落とし直したら、前に生やした行は消える**（`seededRows`）。
  足すだけにすると2回落とした人の変動給が2倍になる。**本人が自分で足した行には触らない。**
- ⚠️ **`supabase/functions/parse-payslip` を触ったら push だけでは本番に反映されない。**
  ダッシュボードで Deploy（オーナー作業）。忘れると、サイトの画面と読み取りで判定が食い違う。
- 読み取りの精度は `node db/eval-payslip.mjs`（16枚 ≒$0.32・**課金される**ので
  デプロイ前チェックには入れない）。見るのは**黙って外した数**だけ。
  ★正解表 `db/fixtures/payslips.expected.json` は**自動更新しない**（退化した出力が正解になって検査が死ぬ）。
