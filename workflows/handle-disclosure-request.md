# 削除依頼・開示請求が来たときの手順

## 目的
掲載内容への抗議、投稿者を教えろという要求、運営者は誰かという照会が届いたときに、
**期限を落とさず・言わなくていいことを言わず・記録を残して**対応する。

## いつ使うか
- 航空会社・団体・個人から「この記述を消せ」という連絡が来たとき
- 「この口コミを書いたのは誰か教えろ」という要求が来たとき
- 契約している事業者（ドメイン・配信・DB・メールの各社）から
  **「あなたの情報を開示してよいか」という照会**が来たとき ← **いちばん急ぐ**
- 弁護士名義の書面、裁判所からの書類が届いたとき

## ⚠️ 前提として絶対に守ること
- **個人のメールから返信しない。** 送受信はすべて `info@pilot-value.com`。
  受信箱でそのまま「返信」を押すと、個人アドレスと表示名が相手に渡る。
  設定と検証の手順は [mail-bot/README.md](../mail-bot/README.md) の「返信経路」。
  送った現物は `node mail-bot/check-reply-headers.mjs <保存した .eml>` で確かめる
  （**表示名も署名も grep では出ない**。必ずこれを通す）
- **SNS・ブログ・知人に一切書かない。** 「こんな要求が来た」の1行が特定の材料になる。
- **感情で返さない。** 事実と手順だけを書く。相手が代理人なら、こちらの文章は全部証拠になる。
- **「対応しない」より「遅れる」ほうが危ない。** 期限のあるものは黙っていると
  こちらの言い分が無いまま話が進む。

---

## 0. 届いた日にやること（30分以内）

1. **原本を保存する。** メールなら `.eml` として保存。郵便なら封筒ごと写真に撮る。
   保存先は `sources-raw/`（リポジトリに入らない）。**リポジトリに commit しない。**
2. **期限を探す。** 書面の中の「◯月◯日までに」「◯日以内に」を探し、カレンダーに入れる。
   期限が書いていなければ **届いた日から7日**を自分の期限として置く。
3. **下の「種類の見分け方」でどれか決める。**
4. **A か B なら自分で返せる。C か D は、その日のうちに弁護士を探し始める。**

---

## 種類の見分け方

| 種類 | 見た目 | 期限 | 誰が返すか |
|---|---|---|---|
| **A. 削除・訂正の依頼** | 「事実と違う」「消してほしい」。ポリシーの窓口か問い合わせフォームから来る | ポリシーで **7日以内に一次回答・14日以内に結論**と約束している | 自分 |
| **B. 投稿者を教えろ** | 「この口コミを書いた人物の情報を開示せよ」 | 相手の指定 | 自分（下の定型で断る） |
| **C. 運営者について事業者から来る照会** | 契約している事業者からの「開示してよいか」という照会 | **数日〜2週間。短い** | 自分で返せるが、**弁護士に見せてから出す** |
| **D. 弁護士名義の書面・裁判所からの書類** | 代理人の署名、裁判所の印、事件番号 | 書面に書いてある | **弁護士。自分で返さない** |

---

## A. 削除・訂正の依頼が来たとき

### A-1. 受け付けたことを7日以内に返す（結論はまだ出さなくていい）
ポリシーで約束した期限。**内容の判断より先に、受け取ったことだけ返す。**

> ご連絡ありがとうございます。ご指摘の件、確認を進めております。
> 確認の結果は◯月◯日までにご連絡いたします。
> （不足があれば）恐れ入りますが、該当するページの URL と、該当箇所を
> そのまま引用したものをお送りいただけますでしょうか。

### A-2. 中身を確かめる
| 指摘の種類 | 確かめる場所 |
|---|---|
| 年収の数値が違う | [salary-data.mjs](../salary-data.mjs)（唯一の正）と [salary-sources.mjs](../salary-sources.mjs)（出所台帳）。`node check-salary.mjs` で全ページの整合も見る |
| 海外の評判の引用がおかしい | そのページの出典表示。原文と訳を突き合わせる |
| 口コミの中身 | 管理者ページで該当の投稿を出す。投稿時の審査で落とすべきものが通っていないか |
| 事実と違う記述 | 出所をたどれるか。**たどれないなら直す。** |

### A-3. 結論を14日以内に返す
**3つのどれかを、理由をつけて返す。**

1. **直す** — こちらの誤りだった場合。直したうえで、直した旨と反映日を返す。
   数値なら [workflows/update-salary.md](update-salary.md) の手順で直す（出所も同じコミットで入れる）。
2. **消す** — 個人が特定される、機密にあたる、出所をたどれない場合。
3. **そのまま載せる** — 出所があり、意見・感想として書かれており、公益性がある場合。
   **なぜそう判断したかを必ず書く。** ここを書いておくと、後で争いになったときに
   「言われても検討しなかった」と言われずに済む。

> ご指摘いただいた箇所について確認いたしました。
> 当該の記述は、◯◯（出所）に基づいて掲載しているもので、
> 投稿者個人の体験に基づく意見・感想として公開しております。
> このため、削除ではなく現状のまま掲載を継続する判断といたしました。
> 追加の資料をお持ちでしたら、あらためて確認いたします。

**緊急性が高いと判断したら、確認が終わる前に一時的に非表示にしてよい**（ポリシーにそう書いてある）。
ただし**「揉めたから消した」の記録を残さない。** 判断の理由を自分用に書いておく。

## B. 「投稿者を教えろ」と言われたとき

**サイトは、投稿者を辿れない作りになっている。** これは断る口実ではなく事実で、
そのまま伝えてよい（技術的な詳細は書かない）。

> お問い合わせありがとうございます。
> PILOT VALUE は匿名での投稿を前提に運営しており、
> 投稿から投稿者を特定できる情報は、正当な法的手続きによる場合を除きお伝えしておりません。
> 掲載内容そのものについてのご指摘であれば、
> 該当する URL と該当箇所をお知らせいただければ確認いたします。

**やってはいけないこと**
- 「投稿者は◯◯社の人のようです」のような**推測を返す**
- 投稿の件数・時期・属性など、**絞り込みの材料になる情報を返す**
- 「教えられませんが、その投稿は消しました」と**言いながら消す**（消したこと自体が答えになる）

**相手が正式な手続きを取ってきたら（弁護士名義・裁判所経由）→ D へ。自分で答えない。**

---

## C. 事業者から「あなたの情報を開示してよいか」という照会が来たとき

**これがいちばん急ぐ。** 契約している事業者が、第三者からの請求を受けて、
契約者本人に「開示してよいか」と聞いてくる形式のもの。

### C-1. 期限を最優先で確認する
**回答しないと「異議なし」として扱われ、こちらの言い分が無いまま開示されることがある。**
届いた日にカレンダーへ入れる。

### C-2. その日のうちに弁護士を探す
**回答は自分で書けるが、出す前に弁護士に見せる。** 一度出した文章は取り消せない。
- 探し方は「発信者情報開示 意見照会 弁護士」で検索。**IT・ネット分野を扱っている事務所**を選ぶ
- 初回相談は1万円前後のところが多い。**この段階で相談することに意味がある**
- 弁護士にはこの手順書と、サイトのポリシーページ、出所台帳の存在を伝える

### C-3. 回答に必ず入れる内容（弁護士に確認してもらう前提の下書き）
- **開示に同意しない**旨をはっきり書く
- **なぜ権利侵害が明らかでないか**を書く:
  - 掲載している年収などの数値には**公開資料に基づく出所がある**（台帳で管理している）
  - 海外の評判は**原文の忠実な訳の引用**で、末尾に**出典を明記**している
  - 投稿は**個人の体験に基づく意見・感想**として掲載しており、
    個人や運航を特定できる記述・機密にあたる記述は**投稿時の審査で落としている**
  - サイトには**削除・訂正の窓口**があり、**7日/14日の回答期限を公開**している。
    請求者はその窓口を使っていない（使っていない場合）
- **返信先は `info@pilot-value.com`。** 個人の連絡先を書かない

### C-4. 通知が届く状態を保つ（普段からやっておくこと）
**照会に気づかなければ、何をしても無意味になる。**
- 契約している各社の連絡先が `info@pilot-value.com` になっていること
- `info@pilot-value.com` が実際に受け取れていること（転送先が生きているか、迷惑メールに入っていないか）
- **3か月に1回、自分でテスト送信して届くことを確かめる**

---

## D. 弁護士名義の書面・裁判所からの書類が届いたとき

**自分で返さない。返事をする前に弁護士に渡す。**

1. **原本を保存する**（封筒・消印・受け取った日を含めて）
2. **期限を確認する**（裁判所からの書類には必ず期限がある。**落とすと不利に確定する**）
3. **その日のうちに弁護士に連絡する。** C-2 と同じ探し方
4. **サイトの記述をこの時点で消さない。** 消すと「都合が悪いから消した」と受け取られる。
   消すかどうかも弁護士と決める
5. **相手に直接連絡しない。** 代理人が立っている相手に本人が直接連絡すると不利になる

**弁護士に渡すもの**
- 届いた書面の原本
- サイトのポリシーページ（[policy.html](../policy.html) / [en/policy.html](../en/policy.html)）
- 数値の出所の方針（[DATA-PROVENANCE.md](../DATA-PROVENANCE.md)）
- 口コミの掲載基準（ポリシーページに書いてある）
- これまでのやり取りの記録

---

## 記録の残し方

**やり取りは全部残す。** 後で「対応しなかった」と言われないための材料になる。

- 原本と返信の `.eml` は `sources-raw/` に日付つきで置く（**リポジトリに commit しない**）
- 判断の理由は自分用に1行でよいので書く（何を根拠に、なぜそうしたか）
- **サイトを直した場合は、その commit が記録になる。** commit メッセージに
  「指摘を受けて◯◯を訂正」と書けば、日付と内容が残る（**相手の名前は書かない**）

---

## やってはいけないこと（まとめ）

| やってはいけない | なぜ |
|---|---|
| 個人のメールから返信する | 表示名とアドレスが相手に渡る。1通で終わる |
| 期限を放置する | こちらの言い分が無いまま話が進む |
| 感情的に返す | 全部証拠になる |
| 相手を推測して書く | 「◯◯社の方ですね」は、こちらが誰かのヒントになる |
| 書類が来てから慌てて記述を消す | 都合が悪いから消したと受け取られる |
| SNS や知人に話す | 特定の材料が増える |
| 弁護士名義・裁判所の書類に自分で返す | 不利になる。専門家に渡す |
