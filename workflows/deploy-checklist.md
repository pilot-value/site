# デプロイ前チェック — 何を守っているか

**この文書は [CLAUDE.md](../CLAUDE.md) から切り出したもの。** 走らせ方（`node check.mjs`）は
CLAUDE.md 側にあり、ここにあるのは **各検査が何を約束しているか**。

⚠️ **検査が落ちたら、直す前にここを読む。** どれも過去に実際に壊れた形を1つずつ書き留めたもので、
**検査のほうが正しいことがほとんど**。その画面を触るときも先に読む。

⚠️ 番号は歴史的なもの（手で1本ずつ流していた頃の順）。今は `node check.mjs` が速い順に並べ替えて回す。

    - ★**`.ai-filled` が付いている欄だけ**消す。本人が触った欄は `unmark` で

    ### A) 明細の扱い ──「画像は送らない」と書かない

    実際に起きていること（[parse-payslip/index.ts](../supabase/functions/parse-payslip/index.ts) を
    読んで確かめたもの）は、この順番：

    1. 端末の中で「送る枠」の外を**画像ごと切り落とす**
    2. 端末の中で氏名・社員番号・口座を**画素ごと黒く塗る**
    3. 本人が確認画面で見て、押す
    4. **枠の中だけを送る**（Edge Function → Anthropic の API）
    5. 読んだら捨てる。ストレージにも DB にもログにも書かない

    つまり **「画像は送りません」は嘘**、「黒塗りしてから送る・保存しない」が本当。
    端末を出ないのは**枠の外**と**塗った部分**であって、画像そのものではない。
    だから「枠の外は端末を出ません」「the un-redacted image never leaves your device」は
    **事実なので禁止していない**。禁則は主語を「画像そのもの」に固定してある。

    ⚠️ **この検査は、同じ嘘を2回書いたから広げたもの。**
    2026-08-13 に `pay-report.html` で一度直し、`db/test-payslip-redact.mjs` に
    「二度と書かない」検査を置いた。**ところがその検査は `pay-report.html` の2枚しか見ていなかった。**
    2026-09-20、オーナーの指摘でサイト全体を見たら、同じ嘘が4か所に残っていた：

    - `index.html` / `en/index.html` の §4 …… **同じ1枚の中で §7・§8 と矛盾**していた
      （§7 は「黒塗りしてから送信・保存しません」と正しく書いてある）
    - `actual-pay.js`（REAL PAY の錠前）…「サーバーには送られません」
    - `airlines/premium-auth-lock.js` …… 「画像は端末から出ません」。**226枚に出ていた**
    - `my-value.html` / `personal-data.html` の meta …「端末内で処理され」

    → 検査を**2枚からサイト全体（HTML ＋ 共有 JS）へ広げ**、`db/test-payslip-redact.mjs` 側の

    ### B) 画面に出る数を HTML に直書きしない

    `community.html` の上の帯には `247` / `17` / `1,203` が **HTML に直書き**されていた。
    JS は一度もそこを書き換えていないので、**実データと何の関係も無い数字**がずっと出ていた。
    日本語版は直したが**英語版だけ直し忘れ**、2026-09-19 には1枚の中で

    - 上の帯 …… 「247 Reviews」「1,203 Registered members」
    - すぐ下の見出し …… 「38 reviews」（**こちらが本物**）

    と食い違っていた。守るのは3つ ──
    ① JS が書き換える欄は HTML に数字を持たせない（＝ JS が動かなければ「—」で出る）／
    ② **日英で欄の集合が同じ**（片方だけ直すと、また今回の形になる）／
    ③ 直書きしてよいのは SSOT から来る定数だけ（掲載社数は `salary-data.mjs` の社数と突き合わせる）。

    ⚠️ **会員数は出さないことにした**（2026-09-20）。匿名では数えられず、出せる数はどれも盛った数になる。

    ⚠️ **口コミの数を数える場所は1つだけ**（2026-09-20 オーナー指示「両方サンプルを数える」）。
    直した直後、帯が「24」・すぐ下の見出しが「38」になった。差の14は `SEED_REVIEWS`＝
    **サイトが自前で用意したサンプルの口コミ**で、見出しだけが数えていた。
    オーナーの決定は**両方が数える**＝どちらも 38。
    そこで `community.html` / `en/community.html` に `totalReviewCount()` を置き、
    **帯も見出しもこの1つの関数から出す**（帯は総数なので絞り込みを通さない。
    会社で絞ると見出しだけ減り、帯は 38 のまま）。
    ★**帯の数を別の場所で数え直さない。** 数える場所が2つあったことが、そもそも
    「247 の上に 38」を生んだ形そのもの。片方だけ直しても画面は普通に動いたまま食い違う。
    ついでに、Supabase から0件しか読めなかった回も描き直すようにした
    （前は0件だと帯が「—」のまま残り、見出しには 14 と出ていた）。
